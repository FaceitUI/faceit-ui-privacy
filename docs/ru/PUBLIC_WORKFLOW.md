# Публичный workflow

Как в этом репозитории обрабатываются пользовательские проблемы и release notes.

## GitHub Issues

- Создавать Issues только для **подтверждённых пользовательских проблем** (воспроизведено пользователем или при тестировании).
- Не открывать публичный Issue на каждую мелкую внутреннюю задачу.
- При сомнениях в формулировке или публичности — сначала подготовить черновик Issue и получить одобрение перед публикацией.

## Что остаётся приватным

Не публиковать здесь:

- Исходный код расширения или release-пакеты
- Секреты, API-ключи или production credentials
- Внутренние детали приватного репозитория `faceit-ui-intake`, сверх того, что уже описано в [Политике конфиденциальности](PRIVACY.md)

## KNOWN_ISSUES.md

- Документировать только **подтверждённые** ограничения или дефекты.
- Без предположений и непроверенных пунктов; не описывать стандартное поведение браузера как баг продукта.
- После исправления: **закрыть** GitHub Issue, указать **версию**, в которой исправлено, и при необходимости обновить [KNOWN_ISSUES.md](KNOWN_ISSUES.md). Историю Issue не удалять.

## CHANGELOG.md

- Добавлять записи только для **заметных пользовательских** изменений в выпущенной версии расширения.

## Проверка maintainer

Перед созданием публичного Issue или добавлением новой публичной информации проверить, не должны ли какие-либо детали остаться внутренними. При сомнениях — согласовать точный текст перед публикацией.
